+# إغلاق المرحلة بعد الدمج
+
+لا تضع `complete` في طلب دمج كود المرحلة. يبقى السجل `reviewing` أو `ready` مع مراجعة Claude الفعلية وبصمة المصدر الصحيحة. بعد حل العوائق ونجاح بوابة الأدلة، يُتحقق من حماية GitHub ومن الفحوص الحية على آخر SHA قبل الدمج، دون تجاوز الإدارة.
+
+بعد دمج كود المرحلة ونجاح سير `Project quality` على commit الدمج:
+
+1. من طرفية VS Code، اجلب `main` وتحقق من PR ورقم commit الدمج. أنشئ `completion/NN` من **commit الدمج نفسه** بمجلد نظيف. لا تنشئ الفرع من نسخة كود أحدث.
+2. شغّل `npm run phase:complete -- NN PR_NUMBER` أو مهمة VS Code المخصصة. يستعمل الأمر مصادقة `gh` الموجودة؛ ينفذ قراءات فقط. يحتاج الوصول إلى المستودع وPR وActions وcheck suites وقراءة حماية الفرع. لا تطبع رمزًا ولا تضعه في ملف أو وسيطة.
+3. تتأكد الأداة من خصوصية المستودع، PR مدمج للفرع الصحيح، حماية main التقليدية مع required checks مربوطة بتطبيق GitHub Actions، strict updates، تطبيق الحماية على الإدارة، منع force push والحذف، حل المحادثات، وعدم وجود review bypass. الحماية عبر rulesets وحدها غير مدعومة بهذا المحقق؛ لا تُعامل كنجاح ضمني ولا يُعطّل أي ruleset.
+4. تُقرأ أحدث محاولة لسير `quality.yml` على رأس فرع المرحلة وعلى commit الدمج، بما فيها صفحات نتائج API. يجب أن تنجح الفحوص الثلاثة `reference-quality` و`governance-security` و`phase-evidence` فعلًا؛ skipped وneutral والفشل لا تُقبل. لا تُختار محاولة نجاح أقدم بدل محاولة حديثة فاشلة.
+5. بعد نجاح التحقق فقط، ينشأ `docs/phases/NN/attempts/completion/record.json` ويتغير `docs/phases/status.json`. يظل `activePhase` كما هو وتظل المرحلة التالية `planned`. لا تكتب الأداة فوق سجل إغلاق موجود ولا تنفذ push أو merge.
+6. أضف الملفين إلى فهرس Git وشغّل `npm run gate` ثم `npm run phase:verify` من VS Code. افتح PR مستقلًا لفرع الإغلاق. يُسمح في هذا الطلب بهذين الملفين فقط؛ تعديل الكود أو السياسة أو حتى تقرير مراجعة مستثنى من البصمة يرفضه الفحص.
+7. تحقق مباشرة من PR الإغلاق وحمايته وفحوص آخر SHA ثم ادمجه عبر المسار المحمي. انتظر نجاح فحوص `main` على دمج سجل الإغلاق، واجلب النتيجة قبل بدء المرحلة التالية. يمنع الفاحص اعتبار سجل مرحلة سابقة مكتملًا ما لم يوجد السجل نفسه في `main` ضمن تاريخ الفرع.
+
+`npm run gate` فحص **اتساق محلي**: يقارن سجل الحالة المسموح به، ويقرأ مراجعة Claude وسجلاتها من commit الدمج الفعلي، ويعيد حساب بصمة ذلك المصدر. لا يمثل تصديقًا من GitHub على ملف JSON محفوظ، ولا تفويضًا للدمج. `npm run phase:verify` يعيد قراءة بيانات GitHub الحية للمراحل المكتملة ويرفض تغير SHA أو فشل الفحوص أو نقص الحماية؛ لا يغني عن فحص PR الإغلاق نفسه. لا تعمل قراءات GitHub داخل الاختبارات المحلية، ولا تُمرر بيانات اعتماد إدارية إلى كود PR عبر CI.
+
+بهذه الطريقة تعتمد مراجعة المرحلة الكود قبل دمجه، وتوثق معاملة منفصلة الوقائع التي أصبحت موجودة بعد الدمج. لا يحتاج سجل الإغلاق إلى مراجعة مصدر جديدة لأن الفاحص يمنع أي تغيير مصدر، وتظل مراجعة PR وحماية GitHub والفحوص مطلوبة. أي تغيير مصدر لاحق يعود إلى جولة مراجعة ضمن الحد الأصلي، ولا يُمرر كتحديث تقارير.

+# منسّق التسليم بين Codex وClaude
+
+المنسّق أداة محلية مملوكة للمشروع، بلا اعتماديات إضافية. يستخدم واجهات CLI المثبتة والمصادقة القائمة، ويُشغّل من مهمة واحدة داخل VS Code. لا يحاكي النقر في نوافذ الإضافات ولا يرسل إلى محادثة Codex الحالية؛ ينشئ جلسات CLI مستقلة تقرأ سياق المشروع وملفات الجولة. الأوامر العامة للإضافتين التي فُحصت لا توفر عقدًا مستقرًا لهذا التبادل. يبقى مسار مراجعة الإضافة اليدوي متاحًا.
+
+## التشغيل
+
+من قائمة `Terminal → Run Task`:
+
+- `SpecialSite: Check coordinator connections`: يفحص وجود الأداتين وخياراتهما وتسجيل الدخول، دون طلب مراجعة.
+- `SpecialSite: Coordinate Codex and Claude`: يبدأ التنسيق للمرحلة المختارة.
+- `SpecialSite: Show coordinator state`: يعرض الطرف الحالي وآخر نتيجة.
+
+البدائل في طرفية VS Code: `npm run coordinator:doctor`، `npm run coordinator:run -- 00`، `npm run coordinator:status -- 00`.
+
+يشترط التشغيل الفرع المسجل للمرحلة النشطة وتقارير Codex الأولية في `round-XX` بعد تجهيز التغييرات المقصودة في Git. ينفذ الجودة إن لم يوجد سجل اختبارات، ثم يحضر طلب CLI ثابتًا بالبصمة والفروق وقائمة الملفات وبصمات التقارير والسجلات. لا يعيد استخدام حزمة الإضافة ذات channel مختلف. عند تعديل النطاق قبل تقديم الحزمة، تحفظ الحزمة غير المقدمة كاملة في attempts مع سبب الأرشفة؛ لا تُؤرشف مراجعة مكتملة أو جولة أُرسلت لتصفير العدّاد.
+
+## دورة العمل
+
+1. يحصل المنسّق على قفل محلي في مجلد Git. لا تشغّل Codex آخر أو تعدّل المصدر يدويًا أثناء الدورة.
+2. يتحقق من أن المصادقة Claude subscription وCodex ChatGPT. يرفض متغيرات API/provider التي قد تحول الطلب إلى فوترة API مختلفة. يستعمل إعدادات Codex الافتراضية دون config المستخدم في الجلسة الآلية، ولا يغيّر إعدادات الحساب الدائمة أو يحدد نموذجًا بديلًا.
+3. يشغّل Claude بـRead/Glob/Grep فقط، safe-mode وrestricted، دون أدوات تنفيذ أو كتابة أو MCP أو hooks/skills مخصصة. يقرأ Claude المصدر والتقارير؛ لا يدّعي تشغيل الاختبارات بنفسه. يحتاج التنفيذ المتوافق لهذه الخيارات، ويتوقف إن كانت النسخة المثبتة لا تدعمها.
+4. يحفظ stdout الأصلي من Claude ومعرّف الجلسة الحقيقي في `claude-raw.json`، ويستورد structured_output دون إعادة صياغة أو تحويل هوية المراجع إلى إضافة VS Code. يثبت request/input/raw hashes ويزيد عدد الجولات المكتملة مرة واحدة فقط.
+5. عند `changes_requested` قبل الجولة الرابعة، يسلّم الرد إلى جلسة Codex مستقلة بصلاحية workspace-write وسياسة رفض طلبات الرفع التلقائي. يطلب إصلاحات ضمن المرحلة وتقارير الجولة التالية، ويتحقق من بقاء الأدلة السابقة دون تغيير، ثم يعيد الجودة والمراجعة.
+6. عند `blocked` أو خطأ أو جودة فاشلة أو الجولة الرابعة، يتوقف ويحفظ السبب. عند `approve` يشغّل بوابة الأدلة؛ العوائق المفتوحة تمنع الجاهزية. لا ينفذ push أو merge أو تغيير حماية أو بدء المرحلة التالية.
+
+لا توجد خيارات bypass أو danger-full-access. فشل sandbox يتسبب في توقف واضح. إذا عدّل Codex أدوات المنسّق نفسها أثناء معالجة ملاحظة، يتوقف المنسّق قبل تشغيل النسخة المعدلة؛ يراجع المشغّل التغيير ويعيد تشغيل الأداة من نسخة ثابتة. هذا يحمي التشغيل الجاري من تبديل الكود الذي يتحقق من نفسه.
+
+## الاستئناف والأدلة
+
+الحالة والسجل ومخرجات العمليات محفوظة في `docs/phases/NN/attempts/coordinator/`. يتوقف كل subprocess عند المهلة ويُغلق فقط شجرة العملية التي بدأها المنسّق. لا تُطبع بيانات تسجيل الدخول؛ ما يُعرض هو حالة الاتصال والمرحلة.
+
+عند الاستئناف، لا يُعاد استدعاء Claude إذا وصل الرد الخام الصحيح؛ يُستورد الرد الموجود. وإذا اكتمل الاستيراد وانقطع تحديث الحالة، يُصالح العدد مع الرد الموجود. إعادة التشغيل بعد خطأ اتصال قد ترسل طلبًا جديدًا فقط إذا لم تصل نتيجة صالحة؛ الطلب الفاشل محفوظ كمحاولة تقنية ولا يُحسب مراجعة مكتملة. فشل الجودة يتطلب حفظ محاولة الاختبار قبل إصلاحها وإعادة تشغيل جولة لم تُقدّم. لا يوجد retry خفي غير محدود.
+
+قفل العملية الحية يمنع التشغيل الثاني. بعد تعطل العملية بالكامل يمكن تشغيل `node scripts/governance/coordinator.mjs unlock`؛ يرفض الأمر إزالة قفل يخص PID حيًا. لا تُحذف تقارير أو جولات عند فك القفل.
+
+الفحص المحلي يثبت اتساق الملفات والرد الذي عاد من العملية، وليس هوية المزود تشفيريًا أو حماية GitHub. تقارير الاختبارات الصناعية لا تُستورد في سجل المشروع. اختبار النقل الحي المعزول تحت `attempts/coordinator-smoke-*` لا يُحسب مراجعة مشروع، ولا يثبت وحده سلامة إصلاح آلي للمصدر. مراجعة المرحلة الفعلية تستخدم `round-XX` وقواعدها الأصلية.
+

+export function validateCliPacket(request, base, load) {

+  if (sha256(load(`${base}/claude-input.txt`)) !== request.inputHash) throw new Error('CLI input changed');

+  if (new Set(tests.checks.map((c) => c.name)).size !== tests.checks.length || required.some((name) => !tests.checks.some((c) => c.name === name && c.command && c.startedAt && c.finishedAt && c.exitCode === 0))) throw new Error('Required quality checks are incomplete');

+// Recompute a historical source fingerprint; never trust a fingerprint in a record alone.
+export function sourceDigestAt(revision) {
+  if (!/^[a-f0-9]{40}$/.test(revision)) throw new Error('Invalid source revision');
+  const files = git('ls-tree', '-r', '--name-only', '-z', revision).split('\0').filter(Boolean)
+    .filter((p) => p !== 'docs/phases/status.json' && !/^docs\/phases\/\d{2}\/(round-\d{2}|attempts)\//.test(p)).sort();
+  return sha256(files.map((p) => {
+    let bytes = execFileSync('git', ['-c', `safe.directory=${process.cwd()}`, 'show', `${revision}:${p}`], { maxBuffer: 32 * 1024 * 1024, windowsHide: true });
+    if (!/\.(png|jpe?g|zip)$/i.test(p)) bytes = Buffer.from(bytes.toString('utf8').replace(/\r\n/g, '\n'));

+export function runProcess(executable, args, { input = '', cwd = process.cwd(), timeoutMs = 20 * 60 * 1000, onProgress = () => {} } = {}) {
+  return new Promise((resolveResult, reject) => {
+    const child = spawn(executable, args, { cwd, shell: false, windowsHide: true, stdio: ['pipe', 'pipe', 'pipe'] });
+    let stdout = '', stderr = '', error = null, timedOut = false;
+    const stop = () => {
+      timedOut = true;
+      if (child.pid && process.platform === 'win32') spawnSync('taskkill.exe', ['/PID', String(child.pid), '/T', '/F'], { windowsHide: true, stdio: 'ignore' });
+      else child.kill('SIGTERM');
+    };
+    const timer = setTimeout(stop, timeoutMs);
+    const heartbeat = setInterval(() => onProgress('running'), 15000);
+    const interrupt = () => { error = new Error('Coordinator interrupted'); stop(); };
+    process.once('SIGINT', interrupt); process.once('SIGTERM', interrupt);
+    child.on('error', (e) => { error = e; });
+    child.stdin.on('error', (e) => { if (e.code !== 'EPIPE') error = e; });
+    for (const [stream, name] of [[child.stdout, 'stdout'], [child.stderr, 'stderr']]) {
+      stream.setEncoding('utf8'); stream.on('data', (data) => {
+        if (name === 'stdout') stdout += data; else stderr += data;
+        if (stdout.length + stderr.length > 16 * 1024 * 1024) { error = new Error('Provider output exceeded limit'); stop(); }
+      });
+    }
+    child.on('close', (code, signal) => {
+      clearTimeout(timer); clearInterval(heartbeat); process.removeListener('SIGINT', interrupt); process.removeListener('SIGTERM', interrupt);
+      resolveResult({ exitCode: code ?? 1, signal, stdout, stderr, timedOut, error: error?.message ?? null });
+    });
+    try { child.stdin.end(input); } catch (e) { clearTimeout(timer); clearInterval(heartbeat); reject(e); }
+  });
