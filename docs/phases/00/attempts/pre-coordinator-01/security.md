# المرحلة 00 / الجولة 01 / الفحص الأمني

السطح المفحوص هو المرجع وأدوات الحوكمة وCI فقط؛ لا خدمة إنتاجية أو هوية أو قاعدة بيانات أو مشغل C# في هذا التغيير. لم تُضف اعتماديات أو تحديثات لحزم المرجع. التنفيذ الجديد يستعمل وحدات Node المدمجة وGit وgh المثبتين، ولا يرسل ملفات المراجعة إلى خدمة خارجية.

نجح dependency-audit: صفر ثغرات معروفة مبلغ عنها وقت التشغيل، كما يبين logs/dependency-audit.txt. نجح secret-scan بلا نتائج ضمن 127 ملفًا وقت الفحص؛ هو فاحص أنماط معروفة لا يفحص التاريخ أو entropy، وليس ضمانًا لخلو المشروع من كل سر. نتائج الاختبارات وسجلاتها الخام مرفقة؛ لا أسرار في مدخلات الأوامر الجديدة. يستخدم قارئ GitHub execFileSync بوسائط ثابتة ومستودع ثابت ورقم PR متحقق منه، دون بناء أوامر shell من محتوى المراجعة. لا عمليات كتابة بعيدة أو merge أو push أو شراء من أداة الإغلاق.

اختُبرت حالات رفض الحماية الناقصة وتجاوز الإدارة والـreview bypass وforce push والحذف وفحص غير مربوط بتطبيق Actions والفحوص الناقصة والمتخطاة والفاشلة واختيار تشغيل قديم. اختُبر عدم مرور تغييرات مصدر أو تقارير مراجعة مع سجل الإغلاق. يقرأ الفاحص السجلات الأصلية من commit الدمج ويحسب بصمته بدل الاعتماد على حقول الحالة. رموز gh تبقى في مخزن المصادقة ولا تُقبل كوسائط أو تُطبع عمدًا. CI لا يتلقى token إداريًا ولا يكتب إلى المستودع.

الحدود المتبقية: سجل JSON المحلي ليس تصديقًا تشفيريًا من GitHub؛ يلزم phase:verify الحي والتحقق المنفصل من PR الإغلاق قبل دمجه. الحماية الفعلية ما زالت غير مثبتة مع عائق 403 المسجل سابقًا؛ يجب ألا تُقبل المرحلة كاملة. ليس هذا فحص SAST/DAST أو container/IaC للإنتاج؛ لم يُنشأ ذلك السطح بعد. اختبارات API الجديدة صناعية وليست دليل وصول فعلي. لم تُنفذ هجمات على خدمات خارجية. تحذيرات build الخاصة بـuse client في اعتماديات TanStack وتحذيرات ألوان أدوات الاختبار محفوظة ولم يُعدّل المرجع لإخفائها.
