# بدء تنفيذ المرحلة 00

التاريخ: 2026-09-27. هذا سجل بدء وفحص محلي، وليس مراجعة Claude أو اعتمادًا للمرحلة.

## ما نُفّذ

- فُتحت مساحة `specialsite.code-workspace` في VS Code.
- لم يوجد مستودع Git محلي قبل التهيئة. تأكد الوصول بحساب `nextleapgit` إلى المستودع الخاص `nextleapgit/specialsite` بصلاحية الإدارة؛ أفادت API صراحة أن المستودع فارغ (`409 Git Repository is empty`).
- أُنشئ `main` محليًا وحُفظت نقطة البداية في `cedf3ee`، ثم أُنشئ `phase/00-governance`. لم يُرفع تاريخ مستقل فوق عمل بعيد ولم تُنفّذ عملية دمج.
- ثُبّتت 211 حزمة من ملف القفل بأمر `npm.cmd --prefix reference/prototype ci --no-audit --no-fund`، وجُهّز Chromium لاختبارات المرجع.
- أُضيف `.github/workflows/quality.yml` بفحوص المرجع والحوكمة والأمن وبوابة أدلة المراجعة لطلبات الدمج. إصدارات Actions مثبتة بمعرّفات commits متحقق منها عبر GitHub API؛ صلاحية سير العمل `contents: read`، وحفظ بيانات اعتماد checkout معطل.
- يستخدم فحص المرجع Windows وNode.js 24.12.0 بما يناسب صور المقارنة الحالية. هذه ليست قرارات إصدارات التطبيق الإنتاجي للمرحلة 01.
- توسع `scope.md` بمعرّفات قبول ونطاق ملفات وفحوص صريحة، وأصبح سجل المرحلة `implementing`، مع بقاء المراحل التالية `planned`.
- استُبعد `debug.log` الناتج عن محاولة فتح VS Code داخل البيئة المقيدة من التتبع؛ لا يتضمن سوى رسالة رفض وصول من Crashpad.
- لم يتغير مصدر `reference/prototype` أو تصميمه أو أصوله أو ملف قفله. المخرجات المولدة مثل `node_modules` و`dist` وتقارير المتصفح مستبعدة من Git.
- كشفت محاولة الجودة الأولى أن اختبارات المتصفح تنشئ `reference/prototype/previews/` خارج قواعد التجاهل، فنجحت الفحوص التسعة لكن رُفضت الأدلة لتغير البصمة. حُفظت المحاولة الأصلية في `quality/` دون اعتبارها نجاحًا للبوابة أو جولة مراجعة. أُضيف استبعاد المسار واختبار رجوع للتحقق من ثبات البصمة عند توليد صور المعاينة؛ صور المقارنة المعتمدة داخل `tests/` لم تتغير.

## عائق الحماية الفعلي

أعادت قراءة `repos/nextleapgit/specialsite/rulesets` حالة HTTP 403 بالنص:

> Upgrade to GitHub Pro or make this repository public to enable this feature.

لا تُعد الفحوص المحلية بديلًا للحماية. لم تُغيّر خصوصية المستودع، ولم تُشتر خطة، ولم يُنشأ تجاوز للحماية. توثيق GitHub: https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/about-protected-branches

مشكلة `gh auth status` داخل البيئة المقيدة اختفت عند التحقق خارج قيود الشبكة؛ الحساب صالح. كذلك استُخدم `npm.cmd` دون تعديل سياسة PowerShell.

## الحدود والعمل المتبقي

- نتائج الفحوص الفعلية تُحفظ في سجل منفصل داخل هذه المحاولة عند اكتمال التشغيل، مع السجلات الأصلية وبصمة المصدر. لا تُحتسب المحاولة جولة مراجعة.
- إعداد CI محلي ولم تثبت فحوصه على GitHub بعد. أسماء الفحوص المقترحة لا تُعامل كحماية مفعلة.
- ما زال GOV-00-06، تنفيذ واختبار آلية إغلاق المرحلة بعد الدمج، مطلوبًا قبل طلب اعتماد المرحلة.
- يلزم حل إمكانية حماية المستودع مع الحفاظ على الخصوصية، ثم مراجعة Claude الفعلية، وفحوص GitHub وPR ودمج متحقق منه. لم تُنشأ موافقة أو هوية مراجع.
- لا يبدأ Backend أو المرحلة 01 قبل اكتمال جميع شروط المرحلة 00.

## التراجع

جميع تغييرات التأسيس في فرع المرحلة. نقطة البداية محفوظة في `main` محليًا، ولم يتغير أي مورد إنتاجي. يمكن مراجعة الفرق دون حذف الاعتماديات أو تعديل المرجع.
