# تبادل العمل داخل VS Code

Codex يطور ويوثق ويختبر، وClaude يراجع باستقلالية. كلاهما يقرأ الملفات المشتركة. شغّل رسائل docs/handoff/START.ar.md عند التسليم؛ لا يوجد منسق تلقائي بين الإضافتين في هذا المجلد.

1. Codex يقرأ سجل الحالة ويعمل على المرحلة الحالية وحدها. ينشئ نطاقًا وشروط قبول، ثم تقارير codex.md وsecurity.md وremediation.md في docs/phases/NN/round-XX.
2. بعد تهيئة Git ومزامنة الفهرس مع التغييرات المقصودة، يشغّل `npm run quality -- NN XX`. الأوامر الحالية تختبر المرجع والحوكمة؛ تُضاف فحوص الإنتاج الحقيقية حسب المرحلة قبل قبولها.
3. يشغّل `npm run review:prepare -- NN XX`. تنشأ request.json وclaude-input.txt ببصمة المصدر وجرد الملفات محليًا، دون إرسال إلى نموذج. يتوقف عن تعديل المصدر.
4. شغّل رسالة المراجعة في إضافة Claude. يقرأ النطاق والطلب والمصدر والفروق والسجلات والملاحظات السابقة، ويكتب فقط claude-extension.json وclaude-review.md داخل الجولة. القالب في docs/handoff/claude-extension.template.json.
5. عند انتهاء Claude، يستأنف Codex ويشغّل `npm run review:import -- NN XX`. الأداة تتحقق من البصمة والنطاق والرد الأصلي وترفض الاستبدال أو الاستعمال بعد تغير المصدر. يضيف رقم الجولة المكتملة إلى rounds في سجل الحالة، دون تحرير قرار Claude.
6. تعالج الملاحظات في الجولة التالية مع اختبار رجوع وسجل ثابت IDs. يعيد Claude التحقق من الإغلاق عبر verifiedClosed؛ الملاحظة الصحيحة لا تختفي إذا تجاهلها تقرير لاحق.
7. عند اكتمال الأدلة والموافقة والفحص الأمني، يشغّل `npm run gate` ويتحقق من GitHub وPR وCI على آخر SHA. بوابة محلية ناجحة لا تكفي لدمج غير محمي أو CI ناقص.

أربع جولات مكتملة كحد أقصى، مع إمكان الانتهاء مبكرًا. بعد الرابعة تبقى المرحلة محجوبة إن وجدت عيوب أو تغييرات غير مراجعة. تحفظ المحاولات الفنية السابقة داخل attempts ولا تتنكر كمراجعات مكتملة. إذا تعطل اختبار قبل إرسال الجولة، تحفظ المحاولة كاملة قبل إصلاحها وإعادة الاختبار؛ لا يعاد استعمال أدلة تخص بصمة مختلفة.

تقرير الإضافة ليس سجل CLI ولا موافقة حساب GitHub مستقلًا؛ لا تختلق session ID. أدوات الفحص تثبت اتساق الأدلة لا هوية المزود تشفيريًا. لا أسرار في التقارير، ولا تعطيل لصلاحيات المحرر أو للحماية لإجبار العمل على المرور. لا تُشغّل الطرفين بالتزامن أثناء المراجعة.

بعد الدمج يجب إثبات نجاح فحوص النتيجة وتسجيله قبل بدء التالية. تُنفذ آلية سجل الإغلاق في المرحلة 00 بطريقة لا تتطلب اعتماد الدمج من نفسه، ولا تمرر تغييرات مصدر تحت غطاء تحديث تقارير. عند الاستئناف من محادثة جديدة تُقرأ الملفات والحالة الفعلية، ولا يعتمد التنفيذ على ذاكرة المحادثة القديمة.

تفاصيل أوامر الإغلاق المنفصل والتحقق الحي في [دليل إغلاق المرحلة](../governance/completion.ar.md). لا تُحدّث الحالة يدويًا إلى complete.
