# إنشاء المستودع المحلي والرفع من VS Code

المجلد الجديد لا يحتوي `.git` أو فروعًا منقولة. المستودع المستهدف https://github.com/nextleapgit/specialsite . التنفيذ والرفع يبدأان من VS Code، وليس من عملية جمع الملفات.

افحص أولًا هل يوجد سياق Git فعلي في مكان المشروع الجديد؛ لا تعِد تهيئة مستودع قائم ولا تمسح تاريخه. تحقق من هوية الحساب وصلاحية المستودع ومن تاريخه وملفاته. فشل المصادقة أو 404 لا يثبت أن المستودع فارغ.

إن كان البعيد فارغًا بعد تحقق ناجح، أنشئ main محليًا واحفظ ملفات البدء كـbaseline ثم فرع phase/00-governance، وارفعهما عند بدء المرحلة 00. main الأول مرجع بداية وليس اعتمادًا للمرحلة. إن كان البعيد يحوي عملًا، ابدأ بفرع من main البعيد وأدخل الملفات مع حفظ الموجود؛ لا force push ولا استبدال تاريخ مستقل. التعارض الجوهري غير القابل للحسم يحتاج صاحب المشروع.

مرحلة 00 تضيف CI مناسبًا للبنية الجديدة وتختبر بوابات المشروع وتفعل حماية main: فحوص مطلوبة على آخر SHA، تحديث الفرع مع main، منع force push والحذف، تطبيق الحماية على الإدارة وحل المحادثات. أدوات النموذج ليست CI الإنتاج الكامل؛ تثبت الفحوص الفعلية قبل اعتماد أسماء checks أو وضع complete.

كل مرحلة عبر فرع phase/NN-slug وPR. الدمج بعد مراجعة Claude الموثقة، صلاحية بصمة المصدر، نجاح الفحوص الحية والحماية، وعدم وجود عيوب صحيحة مفتوحة. لا تجاوز بـadmin أو تخطي فحص. بعد الدمج اختبر نتيجته وسجل merge SHA وروابط الأدلة. لا تبدأ التالية إذا فشل main.

تسجيل اكتمال المرحلة بعد الدمج يحتاج آلية تقارير موثقة تُنشأ في المرحلة 00 دون اعتماد دائري؛ لا توضع حقول اكتمال كاذبة في PR لاعتماد نفسه. لا تحويل المستودع إلى عام أو شراء خطة حماية تلقائيًا. التدخل من المستخدم فقط لصلاحيات/تكلفة/قرار جوهري أو أثر غير قابل للتراجع.

## قرار المستخدم المحدث في 2026-09-27

حوّل المستخدم المستودع إلى عام بنفسه وطلب استكمال العمل. هذا القرار يحل محل شرط الخصوصية السابق؛ تُحفظ الرؤية العامة التي اعتمدها، وتظل الحماية والفحوص والمراجعة المستقلة شروطًا إلزامية. تفعيل الحماية لا يعني اعتماد المرحلة. مراجعة المصدر تسبق نجاح phase-evidence الذي يستهلكها، ثم يجب نجاح جميع الفحوص على آخر PR قبل الدمج والتحقق من فحوص النتيجة قبل الإغلاق.
