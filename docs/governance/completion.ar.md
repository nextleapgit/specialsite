# إغلاق المرحلة بعد الدمج

لا تضع `complete` في طلب دمج كود المرحلة. يبقى السجل `reviewing` أو `ready` مع مراجعة Claude الفعلية وبصمة المصدر الصحيحة. بعد حل العوائق ونجاح بوابة الأدلة، يُتحقق من حماية GitHub ومن الفحوص الحية على آخر SHA قبل الدمج، دون تجاوز الإدارة.

بعد دمج كود المرحلة ونجاح سير `Project quality` على commit الدمج:

1. من طرفية VS Code، اجلب `main` وتحقق من PR ورقم commit الدمج. أنشئ `completion/NN` من **commit الدمج نفسه** بمجلد نظيف. لا تنشئ الفرع من نسخة كود أحدث.
2. شغّل `npm run phase:complete -- NN PR_NUMBER` أو مهمة VS Code المخصصة. يستعمل الأمر مصادقة `gh` الموجودة؛ ينفذ قراءات فقط. يحتاج الوصول إلى المستودع وPR وActions وcheck suites وقراءة حماية الفرع. لا تطبع رمزًا ولا تضعه في ملف أو وسيطة.
3. تتأكد الأداة من خصوصية المستودع، PR مدمج للفرع الصحيح، حماية main التقليدية مع required checks مربوطة بتطبيق GitHub Actions، strict updates، تطبيق الحماية على الإدارة، منع force push والحذف، حل المحادثات، وعدم وجود review bypass. الحماية عبر rulesets وحدها غير مدعومة بهذا المحقق؛ لا تُعامل كنجاح ضمني ولا يُعطّل أي ruleset.
4. تُقرأ أحدث محاولة لسير `quality.yml` على رأس فرع المرحلة وعلى commit الدمج، بما فيها صفحات نتائج API. يجب أن تنجح الفحوص الثلاثة `reference-quality` و`governance-security` و`phase-evidence` فعلًا؛ skipped وneutral والفشل لا تُقبل. لا تُختار محاولة نجاح أقدم بدل محاولة حديثة فاشلة.
5. بعد نجاح التحقق فقط، ينشأ `docs/phases/NN/attempts/completion/record.json` ويتغير `docs/phases/status.json`. يظل `activePhase` كما هو وتظل المرحلة التالية `planned`. لا تكتب الأداة فوق سجل إغلاق موجود ولا تنفذ push أو merge.
6. أضف الملفين إلى فهرس Git وشغّل `npm run gate` ثم `npm run phase:verify` من VS Code. افتح PR مستقلًا لفرع الإغلاق. يُسمح في هذا الطلب بهذين الملفين فقط؛ تعديل الكود أو السياسة أو حتى تقرير مراجعة مستثنى من البصمة يرفضه الفحص.
7. تحقق مباشرة من PR الإغلاق وحمايته وفحوص آخر SHA ثم ادمجه عبر المسار المحمي. انتظر نجاح فحوص `main` على دمج سجل الإغلاق، واجلب النتيجة قبل بدء المرحلة التالية. يمنع الفاحص اعتبار سجل مرحلة سابقة مكتملًا ما لم يوجد السجل نفسه في `main` ضمن تاريخ الفرع.

`npm run gate` فحص **اتساق محلي**: يقارن سجل الحالة المسموح به، ويقرأ مراجعة Claude وسجلاتها من commit الدمج الفعلي، ويعيد حساب بصمة ذلك المصدر. لا يمثل تصديقًا من GitHub على ملف JSON محفوظ، ولا تفويضًا للدمج. `npm run phase:verify` يعيد قراءة بيانات GitHub الحية للمراحل المكتملة ويرفض تغير SHA أو فشل الفحوص أو نقص الحماية؛ لا يغني عن فحص PR الإغلاق نفسه. لا تعمل قراءات GitHub داخل الاختبارات المحلية، ولا تُمرر بيانات اعتماد إدارية إلى كود PR عبر CI.

بهذه الطريقة تعتمد مراجعة المرحلة الكود قبل دمجه، وتوثق معاملة منفصلة الوقائع التي أصبحت موجودة بعد الدمج. لا يحتاج سجل الإغلاق إلى مراجعة مصدر جديدة لأن الفاحص يمنع أي تغيير مصدر، وتظل مراجعة PR وحماية GitHub والفحوص مطلوبة. أي تغيير مصدر لاحق يعود إلى جولة مراجعة ضمن الحد الأصلي، ولا يُمرر كتحديث تقارير.

فشل الشبكة أو الصلاحيات أو حماية الخطة يبقي الإغلاق محجوبًا. لا تغيير للخصوصية أو شراء خطة أو دفع تكلفة CI تلقائيًا. سجلات API ليست إثباتًا تشفيريًا؛ يجب التحقق الحي قبل أي دمج مؤهل.

المراجع الرسمية المستخدمة للعقود: [حماية الفروع](https://docs.github.com/en/rest/branches/branch-protection)، [سجلات Actions](https://docs.github.com/en/rest/actions/workflow-runs)، [وظائف Actions](https://docs.github.com/en/rest/actions/workflow-jobs).
