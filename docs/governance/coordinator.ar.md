# منسّق التسليم بين Codex وClaude

المنسّق أداة محلية مملوكة للمشروع، بلا اعتماديات إضافية. يستخدم واجهات CLI المثبتة والمصادقة القائمة، ويُشغّل من مهمة واحدة داخل VS Code. لا يحاكي النقر في نوافذ الإضافات ولا يرسل إلى محادثة Codex الحالية؛ ينشئ جلسات CLI مستقلة تقرأ سياق المشروع وملفات الجولة. الأوامر العامة للإضافتين التي فُحصت لا توفر عقدًا مستقرًا لهذا التبادل. يبقى مسار مراجعة الإضافة اليدوي متاحًا.

## التشغيل

من قائمة `Terminal → Run Task`:

- `SpecialSite: Check coordinator connections`: يفحص وجود الأداتين وخياراتهما وتسجيل الدخول، دون طلب مراجعة.
- `SpecialSite: Coordinate Codex and Claude`: يبدأ التنسيق للمرحلة المختارة.
- `SpecialSite: Show coordinator state`: يعرض الطرف الحالي وآخر نتيجة.

البدائل في طرفية VS Code: `npm run coordinator:doctor`، `npm run coordinator:run -- 00`، `npm run coordinator:status -- 00`.

يشترط التشغيل الفرع المسجل للمرحلة النشطة وتقارير Codex الأولية في `round-XX` بعد تجهيز التغييرات المقصودة في Git. ينفذ الجودة إن لم يوجد سجل اختبارات، ثم يحضر طلب CLI ثابتًا بالبصمة والفروق وقائمة الملفات وبصمات التقارير والسجلات. لا يعيد استخدام حزمة الإضافة ذات channel مختلف. عند تعديل النطاق قبل تقديم الحزمة، تحفظ الحزمة غير المقدمة كاملة في attempts مع سبب الأرشفة؛ لا تُؤرشف مراجعة مكتملة أو جولة أُرسلت لتصفير العدّاد.

## دورة العمل

1. يحصل المنسّق على قفل محلي في مجلد Git. لا تشغّل Codex آخر أو تعدّل المصدر يدويًا أثناء الدورة.
2. يتحقق من أن المصادقة Claude subscription وCodex ChatGPT. يرفض متغيرات API/provider التي قد تحول الطلب إلى فوترة API مختلفة. يستعمل إعدادات Codex الافتراضية دون config المستخدم في الجلسة الآلية، ولا يغيّر إعدادات الحساب الدائمة أو يحدد نموذجًا بديلًا.
3. يشغّل Claude بـRead/Glob/Grep فقط، safe-mode وrestricted، دون أدوات تنفيذ أو كتابة أو MCP أو hooks/skills مخصصة. يقرأ Claude المصدر والتقارير؛ لا يدّعي تشغيل الاختبارات بنفسه. يحتاج التنفيذ المتوافق لهذه الخيارات، ويتوقف إن كانت النسخة المثبتة لا تدعمها.
4. يحفظ stdout الأصلي من Claude ومعرّف الجلسة الحقيقي في `claude-raw.json`، ويستورد structured_output دون إعادة صياغة أو تحويل هوية المراجع إلى إضافة VS Code. يثبت request/input/raw hashes ويزيد عدد الجولات المكتملة مرة واحدة فقط.
5. عند `changes_requested` قبل الجولة الرابعة، يسلّم الرد إلى جلسة Codex مستقلة بصلاحية workspace-write وسياسة رفض طلبات الرفع التلقائي. يطلب إصلاحات ضمن المرحلة وتقارير الجولة التالية، ويتحقق من بقاء الأدلة السابقة دون تغيير، ثم يعيد الجودة والمراجعة.
6. عند `blocked` أو خطأ أو جودة فاشلة أو الجولة الرابعة، يتوقف ويحفظ السبب. عند `approve` يشغّل بوابة الأدلة؛ العوائق المفتوحة تمنع الجاهزية. لا ينفذ push أو merge أو تغيير حماية أو بدء المرحلة التالية.

لا توجد خيارات bypass أو danger-full-access. فشل sandbox يتسبب في توقف واضح. إذا عدّل Codex أدوات المنسّق نفسها أثناء معالجة ملاحظة، يتوقف المنسّق قبل تشغيل النسخة المعدلة؛ يراجع المشغّل التغيير ويعيد تشغيل الأداة من نسخة ثابتة. هذا يحمي التشغيل الجاري من تبديل الكود الذي يتحقق من نفسه.

## الاستئناف والأدلة

الحالة والسجل ومخرجات العمليات محفوظة في `docs/phases/NN/attempts/coordinator/`. يتوقف كل subprocess عند المهلة ويُغلق فقط شجرة العملية التي بدأها المنسّق. لا تُطبع بيانات تسجيل الدخول؛ ما يُعرض هو حالة الاتصال والمرحلة.

عند الاستئناف، لا يُعاد استدعاء Claude إذا وصل الرد الخام الصحيح؛ يُستورد الرد الموجود. وإذا اكتمل الاستيراد وانقطع تحديث الحالة، يُصالح العدد مع الرد الموجود. إعادة التشغيل بعد خطأ اتصال قد ترسل طلبًا جديدًا فقط إذا لم تصل نتيجة صالحة؛ الطلب الفاشل محفوظ كمحاولة تقنية ولا يُحسب مراجعة مكتملة. فشل الجودة يتطلب حفظ محاولة الاختبار قبل إصلاحها وإعادة تشغيل جولة لم تُقدّم. لا يوجد retry خفي غير محدود.

قفل العملية الحية يمنع التشغيل الثاني. بعد تعطل العملية بالكامل يمكن تشغيل `node scripts/governance/coordinator.mjs unlock`؛ يرفض الأمر إزالة قفل يخص PID حيًا. لا تُحذف تقارير أو جولات عند فك القفل.

الفحص المحلي يثبت اتساق الملفات والرد الذي عاد من العملية، وليس هوية المزود تشفيريًا أو حماية GitHub. تقارير الاختبارات الصناعية لا تُستورد في سجل المشروع. اختبار النقل الحي المعزول تحت `attempts/coordinator-smoke-*` لا يُحسب مراجعة مشروع، ولا يثبت وحده سلامة إصلاح آلي للمصدر. مراجعة المرحلة الفعلية تستخدم `round-XX` وقواعدها الأصلية.
